# REQ-006 カメラ RTMP のアーカイブと配信、字幕・翻訳、黒板／ホワイトボード補正、サムネイル

- 追加日: 2026-10-26（利用者の指示）
- 状態: 要件として受理。**「カメラ RTMP → アーカイブ＋配信」は喫緊の要件として最優先。**
- 目標水準: 商用の WebRTC サービスと同等の品質を目指す。WebRTC はその水準まで段階的に作り込む。

## 要件

| ID | 内容 | 優先 |
|---|---|---|
| R6-1 | RTMP で送られてくるカメラ映像を **アーカイブ（録画）しながら配信** する | 最優先 |
| R6-2 | 配信・録画の **エンドポイントを API で設計・作成** できる（REQ-002） | 最優先 |
| R6-3 | **1 対 1**（双方向・低遅延）と **1 対多**（多数視聴） | 1 対多は HLS で済。1 対 1 は WebRTC |
| R6-4 | **字幕**（音声認識）と **字幕の翻訳** | 高 |
| R6-5 | **黒板カメラの補正**（台形補正、反射・白飛びの補正、コントラスト強調、チョーク文字の強調） | 高 |
| R6-6 | **ホワイトボードを撮るカメラ** にも対応し、講師カメラと **同時に配信** | 高 |
| R6-7 | **複数チャネル** の動画（同時配信、合成） | 高 |
| R6-8 | **静止画のキャプチャ**（API・予定・板書の変化で自動） | 中 |
| R6-9 | **動画のサムネイルの自動生成** | 中 |

## 実現の方針

### 共通の前提: codec worker
R6-4〜R6-9 はすべて「デコード → 処理 → 必要ならエンコード」を要する。仕様 2.1・3.1 の codec worker（隔離プロセス）を先に作る。

- デコード・エンコードは外部コーデック（仕様 2.1 で許可）。候補と注意:
  - H.264 エンコード: x264（GPL。配布形態に注意）、openh264（BSD、Cisco のバイナリなら特許ライセンス付き）、VideoToolbox（Mac）、NVENC / AMF / QSV（REQ-004）。
  - H.264 デコード: openh264、libavcodec のデコーダー API のみ（LGPL）、ハードウェア。
  - AAC デコード: libavcodec のネイティブ AAC デコーダー（LGPL）など。fdk-aac は再配布条件に注意。
  - JPEG（静止画・サムネイル）: libjpeg-turbo（BSD 系）。
- 選定は ADR で、ライセンス・特許・更新責任者を記録してから（仕様 2.1）。
- 色変換・リサイズ・台形補正・合成は自前（仕様 2.1）。

### R6-1 アーカイブ＋配信
- 入力は 1 本、出力は「ライブ（HLS、後に WebRTC/LL-HLS）」と「録画」に分岐。録画の遅れで視聴を止めない（仕様 5.3：キューを分ける）。
- 録画は不変のセグメント＋索引（仕様 8.4）。REQ-002 の「1 入力を複数予約で共有」と同じ仕組みで、ライブ用セグメントと録画を共有できるようにする。
- 保存先はローカルとオブジェクトストレージ（S3 互換）。保持期限・削除・法的保全を区別。
- 再生は VOD の HLS（ENDLIST 付き）と MP4 書き出し。

### R6-3 1 対 1 と 1 対多
- 1 対多: HLS（実装済み）→ LL-HLS → MoQ。
- 1 対 1: WebRTC（P3）。暗号（DTLS）の扱いを ADR で決め、独立した監査を手配してから公開（仕様 2.2・15.3）。

### R6-4 字幕と翻訳
- 音声 → 音声認識（Whisper 系を GPU サーバーで。Mac では動かさない）→ 字幕の断片（時刻付き）。
- 翻訳は LLM または翻訳 API。言語ごとに字幕トラックを作る。
- 出力: HLS の字幕トラック（WebVTT、EXT-X-MEDIA TYPE=SUBTITLES）、録画には字幕ファイルを保存、WebRTC には DataChannel で送る。
- 遅延の予算を明示する（認識に数秒かかる。ライブでは字幕が遅れて出ることを許すか、映像を遅らせて合わせるかを選べる）。
- 外部処理の部品（REQ-005）として隔離。外部サービスへ音声を送る場合は、送信先と保存の有無を契約・設定で明示する。

### R6-5 / R6-6 黒板・ホワイトボード
- 台形補正（4 点のホモグラフィ。初期は手動で 4 隅を指定、後に自動検出）。
- 反射・照明むらの補正（背景推定と除去）、コントラスト強調、ホワイトボードは白地化、黒板はチョーク文字の強調。
- 講師カメラと板書カメラを別チャネルで同時に配信、または合成（PinP・並べる）。
- 板書の変化検出で静止画を自動保存（R6-8）。

### R6-8 / R6-9 静止画とサムネイル
- API で今のフレームを JPEG で取得。予定・一定間隔・板書の変化で自動保存。
- サムネイルは録画ごとに自動生成（シーンの変化・ぶれの少なさ・黒画面の除外で選ぶ）。HLS 用の画像プレイリスト（I-frame / image media playlist）も後で。

## 受け入れ試験（案）

| ID | 内容 | 合格条件 |
|---|---|---|
| AC-R6-01 | RTMP カメラ 1 台で 2 時間配信しながら録画 | 視聴が途切れない、録画の欠落 0、録画を VOD で再生できる |
| AC-R6-02 | 録画ストレージを遅くする | 視聴の遅延・途切れが増えない（録画側だけが遅れる） |
| AC-R6-03 | 日本語の講義音声に字幕と英訳 | 字幕のずれ・遅延を測定し、目標内（目標値は P0 で決める） |
| AC-R6-04 | 斜めから撮った黒板を補正 | 補正後の板書が正面化され、文字の判読性が上がる（評価方法は P0 で決める） |
| AC-R6-05 | 講師カメラと板書カメラを同時に配信・録画 | 2 チャネルの時刻が揃う（ずれ 1 フレーム以内） |
| AC-R6-06 | サムネイルの自動生成 | 黒画面・ぶれた画像を選ばない |
