# REQ-008 OBS のような制作機能（サーバー側のプロダクション）

- 追加日: 2026-10-26（利用者の指示「OBS みたいな機能も入れてください」）
- 状態: 要件として受理。M4（codec worker）・M5（合成）の上に作る。GUI は M12。

## 解釈

OBS Studio の「シーンを組み、切り替え、混ぜて、配信・録画する」機能を、**サーバー側で動く制作機能**として SENCA に持たせる。操作は GUI と API から。あわせて、送り手側の道具（ブラウザからカメラ・画面を送る）を用意する。

## 要件

| ID | 内容 | OBS での名前 |
|---|---|---|
| R8-1 | **シーン**: 複数のソースを重ねて配置した画面を保存・編集できる | Scene |
| R8-2 | **ソース**: ライブ入力（カメラ・板書カメラ・画面）、画像、文字（時計・テロップ）、色、録画の再生（VOD をソースに）、メディアファイル | Sources |
| R8-3 | **配置**: 位置・大きさ・切り抜き・回転・重なり順・不透明度・表示/非表示 | Transform |
| R8-4 | **シーンの切り替え**とトランジション（カット、フェード、ワイプ、スティンガーは後続） | Transitions |
| R8-5 | **プレビュー／プログラム**: 次のシーンを準備して確認し、切り替える | Studio Mode |
| R8-6 | **音声ミキサー**: ソースごとの音量・ミュート・遅延（映像との同期）・メーター、マスター | Audio Mixer |
| R8-7 | **フィルター**: 色補正、クロマキー、マスク、シャープ、板書補正（REQ-006）、ノイズ抑制・ゲート・コンプレッサー | Filters |
| R8-8 | **出力**: 合成結果を配信（HLS / WebRTC / MoQ / RTMP 送出 / PaaS）と録画へ同時に | Stream / Record |
| R8-9 | **操作**: API・GUI・予約（REQ-002）・外部の操作盤（Stream Deck など、後続） | Hotkeys |
| R8-10 | **送り手の道具**: ブラウザからカメラ・マイク・画面を WHIP（WebRTC）で送る。OBS 本体（RTMP / WHIP / SRT）からも送れる | — |

## 設計の方針

- 制作は **パイプラインの部品「合成（compositor）」** として実装する（REQ-005）。シーンは合成部品の設定、切り替えは設定の新世代への切り替え（仕様 5.1：検証してから commit、失敗したら旧世代を継続）。
- 合成・色変換・リサイズ・トランジション・音声ミキシングは **自前**（仕様 2.1）。GPU で行う場合も自前のシェーダー（REQ-004）。
- 文字の描画（フォントのラスタライズ）は外部ライブラリ候補（例: FreeType 相当、ライセンスを ADR で確認）。
- 時刻: 合成の出力は自前の出力クロックで一定のフレームレートを刻み、各ソースの最新フレーム（期限内）を使う。遅れたソースは前のフレームを保持し、音声は音声クロック基準で同期する（仕様 4.3）。
- 制作の操作は API の resource（`/productions`、`/productions/{id}/scenes`、`/productions/{id}/program`）として持ち、GUI は API だけを使う（REQ-002）。
- 冗長化（REQ-005 の 1+1）にも対応できるよう、合成の状態（現在のシーン・トランジションの進行）は制御面に保存する。

## API（案）

| Method / Path | 動作 |
|---|---|
| POST /productions | 制作（出力解像度・フレームレート・音声形式）の作成 |
| POST /productions/{id}/scenes | シーンの作成（ソースと配置） |
| PATCH /productions/{id}/scenes/{scene} | シーンの編集（If-Match） |
| POST /productions/{id}/preview | プレビューに載せるシーン |
| POST /productions/{id}/transition | プログラムへ切り替え（種類・時間） |
| PATCH /productions/{id}/audio/{source} | 音量・ミュート・遅延 |
| POST /productions/{id}/outputs | 出力（配信・録画・送出） |

## 追記（2026-10-26）: Web のスイッチャーとカメラ操作盤

| ID | 内容 |
|---|---|
| R8-11 | **Web のスイッチャー**: ブラウザでプレビュー／プログラム、シーンの切り替え、トランジション、音声ミキサー（メーター付き）を操作できる |
| R8-12 | **Web のカメラ操作盤**: ブラウザでズーム・フォーカス・露出・ホワイトバランス・プリセット、PTZ のジョイスティック操作ができる |
| R8-13 | **「このコントロールにつなげば操作できる」**: カメラ（スマホのアプリ、ONVIF の IP カメラ、VISCA over IP の PTZ カメラ）が SENCA の制御面につながっていれば、どれも同じ操作盤で扱える |

### 方式

- カメラごとの違いは **制御アダプター** に閉じ込める: SENCA アプリ（制御チャネル）、ONVIF（Profile S の PTZ・Imaging）、VISCA over IP。操作盤は共通の操作（`zoom`、`focus`、`exposure`、`white_balance`、`preset.recall`、`pan_tilt`）だけを使う。
- できない操作はカメラの能力（capabilities）で示し、操作盤は出さない（黙って無視しない）。
- 遅延: 操作は WebSocket（M8 以降は DataChannel も）で送り、ジョイスティックは連続値を一定間隔で送る。目標は操作から反映まで 200 ms 以内（同一拠点）。
- 権限: `camera:control` を新設。誰がいつどのカメラを操作したかを監査ログに残す。同時に複数人が操作する場合の優先（操作権の取得・解放）を持つ。
- プレビューの映像は低遅延（WebRTC、M8 以降。それまでは LL-HLS か JPEG のサムネイル更新）で出す。
- 外部の操作盤（ハードウェアのコントローラー、Stream Deck、スイッチャーの GPI など）は後続。
