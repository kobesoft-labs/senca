# ADR-0006 stream タスクとデータの通り道

- 状態: 採用（2026-11-02）
- 関係: 仕様 3.2・5.1・5.3、REQ-010（R10-1・R10-7・R10-8）

## 決定

- **stream ごとに 1 つのタスク（hub）。** 接続より長生きし、送り手の再接続（猶予 `--reconnect-grace`、既定 30 秒）をまたいで同じ stream として続ける。再接続で epoch を増やし、不連続として扱う。
- **入口は有界のキュー。** 送り手（RTMP・SRT・WHIP など）は hub のキューに `await` で入れる。hub が遅れれば送り手の読み込みが止まり、TCP の背圧になる。
- **出口は 3 つ。**
  1. **ライブ配信（HLS）**: hub の中でセグメント分割と多重化を 1 回だけ行い、結果（`Bytes`）を `LiveCache`（メモリ）に置く。HTTP は `LiveCache` から返す。ディスクを通らない。
  2. **購読者（RTMP play・WebRTC・MoQ・SRT 出力・外部への push・合成）**: `broadcast` で AU（`Bytes` の参照）を配る。遅い購読者は取りこぼしを検出し、次のキーフレームから再開する（他を待たせない）。新しい購読者には直近の GOP を先に渡す（すぐ再生を始めるため）。
  3. **録画**: 完成したセグメントを録画の書き手（ADR-0005）へ有界キューで渡す。あふれたら落として欠落を記録する。
- **コピーしない。** 受信した payload は一度だけ `Bytes` に組み立て、以後は参照を配る。形を変える所（TS・fMP4 への多重化、暗号化）だけで新しいバイト列を作る（R10-7）。
- **ノード内はネットワークを使わない。** 部品はメモリのチャネルでつなぐ。codec worker だけは別プロセスで、パイプ（と大きなフレームは共有メモリ）でつなぐ（R10-8）。
